## Codebase Patterns
- Runtime app, component, and optimizer code must not import, require, bundle, or load PvPoke vendor JavaScript; local PvPoke execution remains isolated to sync tooling.
- Moveset variant work must read `.opencode/skills/gbl-optimizer/SKILL.md` and the required optimizer documents before changing ranking inputs, simulation data, scoring, or diagnostics.
- Required optimizer docs: `docs/pokemon-go-team-optimization.md`, `docs/team-optimization/scoring-model.md`, `docs/team-optimization/lineup-structures.md`, `docs/team-optimization/coverage-threat-pools.md`, `docs/team-optimization/safety-consistency-bulk.md`, `docs/team-optimization/type-effectiveness.md`, `docs/team-optimization/role-scoring.md`, `docs/team-optimization/data-inputs.md`, and `docs/team-optimization/validation.md`.
- Implement behavioral changes test-first and record the failing and passing focused test commands in each iteration log.
- Preserve unrelated worktree changes and do not remove generated files outside the tested stale-variant cleanup boundary.
- Initialize `vendor/pvpoke` with `git submodule update --init vendor/pvpoke` before running tests that validate bundled PvPoke source data.
- Keep species ID, species display-name, and move spelling aliases in `lib/data/aliases.ts`; distinguish battle-state aliases from moveset variants and retain source provenance until canonical ranking deduplication finishes.
- Purified Return eligibility requires an exact checked-in shadow counterpart for the canonical choosable form and the non-shadow form's finite `level25CP` at or below the format cap; never infer shadow forms from tags, family, or Dex identity.
- Legacy move availability approvals are canonical species-move pairs classified as event-exclusive; exhaustive tests must map every checked-in `legacyMoves` pair to an explicit allow or exclude expectation.
- Ranking sync validates and returns `RankingSyncResult` with unaggregated source movesets, nullable fast/charged usage, per-source alias provenance, and one optional override set per supported format; keep override path knowledge and missing-file handling inside `lib/sync/adapter.ts`.
- Normalize ranking move usage per species entry and fast/charged slot before category weighting; retain exact observed movesets and overrides above usage-only evidence, then sort weighted evidence by category occurrence, exact Overall use, and move ID.
- Move-mechanics filtering may reject only strictly dominated usage-only speculation; observed and override moves remain eligible, and status effects or distinct type coverage keep moves strategically incomparable until simulation.
- Moveset derivation preserves the eligible preferred Overall set first, retains exact observed and override sets, limits expansion to two fast and four charged moves, generates only single-move substitutions around observed anchors, and emits at most eight canonical variants using the current sync Pokemon snapshot for availability.
- Invalid preferred Overall sets retain rejection evidence and the original PvPoke score prior; ranking sync derives replacements before CSV conversion, changes only Overall move columns, and omits an Overall row only when no complete eligible candidate exists.
- Emitted Overall rankings are the authoritative TeamRanker opponent pool; resume sync fingerprints each format, prunes changed format caches, and initializes canonical deduplicated targets with sanitized defaults before simulation.
- Simulation projection bypasses the destructive full sync pipeline, derives candidates with no-op persistence boundaries, projects alternates only for sanitized top-150 Overall targets with multiple candidates, and recognizes stale files only through strict canonical variant filenames and required shield scenarios.
- Moveset variant manifest parsing and canonical serialization live in `lib/data/movesetVariantManifest.ts`; source hashing and pure generated-manifest construction live in `lib/sync/movesetVariantManifest.ts`, and shared hard caps come from the data-layer manifest contract.
- Manifest validation rejects known species aliases and requires canonical uppercase ASCII move IDs instead of normalizing alternate representations, preventing parallel species storage keys and moveset variant identities in authoritative generated data.
- Simulation sync consumes ranking-derived candidate sets and sanitized top-150 target ids directly, validates candidates against the fresh Pokemon and move snapshots, keeps defaults on unqualified paths, and writes alternates only to canonical format-scoped variant paths.
